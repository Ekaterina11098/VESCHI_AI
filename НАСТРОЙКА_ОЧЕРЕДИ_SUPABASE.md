# Бесплатный пробный запуск очереди отзывов

## 1. Supabase

Создайте бесплатный проект Supabase. В SQL Editor выполните **весь** файл `supabase_review_queue.sql`. Он создаёт таблицу и атомарные функции очереди. В Settings → API Keys получите секретный ключ формата `sb_secret_...` и адрес проекта `https://....supabase.co`. Секретный ключ **не публикуйте и не вставляйте в исходный код**.

## 2. Streamlit

Добавьте в Settings → Secrets строки `SUPABASE_URL = "https://....supabase.co"` и `SUPABASE_SECRET_KEY = "sb_secret_..."`. Сохраните существующие WB и Telegram Secrets. Разместите все файлы архива в корне прежнего репозитория, включая скрытую папку `.github/workflows`. Убедитесь, что форма отзывов открывается и не сообщает «Очередь ответов недоступна». При первой проверке используйте **реальный отзыв, на который вы хотите ответить**: нажатие «Опубликовать» действительно отправляет ответ в WB, если WB принимает запрос.

## 3. GitHub Actions

В том же репозитории зайдите в Settings → Secrets and variables → Actions → Repository secrets. Добавьте три секрета: `SUPABASE_URL` и `SUPABASE_SECRET_KEY` с теми же значениями, что в Streamlit, и `WB_FEEDBACK_TOKEN` — токен доступа к отзывам кабинета 1 (если у вас используется `WB_TOKEN_1`, укажите его значение под именем `WB_FEEDBACK_TOKEN`). **Не кладите токены или ключи в файлы GitHub**. Workflow `.github/workflows/review-replies.yml` запускается по UTC в минуты 07 и 37; в GitHub Actions можно нажать `Run workflow` для разового запуска. Репозиторий должен быть приватным; следите за бесплатными минутами GitHub Actions.

## Как проверить без реальной публикации

Сначала выполните SQL, задайте Secrets и запустите `Run workflow` без ответов в очереди: успешное завершение подтвердит связь GitHub с Supabase. Затем откройте форму: отсутствие предупреждения подтвердит связь Streamlit с той же базой. Отправку с реальным отзывом проверяйте лишь когда готовы опубликовать выбранный текст. Записей для теста с выдуманным ID в рабочую очередь не добавляйте.

## Ограничения

Интервал 30 минут выбран с запасом к включённым минутам закрытого репозитория GitHub Free; запланированный запуск может задерживаться. Бесплатный Supabase может приостановить неактивный проект. При статусе «требует ручной проверки» или «отправка начата» сначала посмотрите результат в WB; автоматический повтор для этих статусов отключён. Отдельного удаления или редактирования уже одобренного ответа нет. Ключ Supabase открывает серверный доступ к базе и должен оставаться только в Secrets.

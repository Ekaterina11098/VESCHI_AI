# Проверки VESCHI AI

## Как обновить работающего бота

1. Распакуйте ZIP: файлы и папка `pages` лежат сразу в корне архива. Замените **одноимённые файлы в корне репозитория**, в том числе `tg_agent_new.py` и `pages/bot_worker.py`. Не загружайте ZIP в репозиторий как один файл и не создавайте в нём дополнительную папку `VESCHI_AI-main`.
2. Сохраните изменения (Commit changes) в ветке, из которой развёрнуто приложение Streamlit, и перезапустите приложение. Если бот запущен отдельной командой `python tg_agent_new.py`, перезапустите этот процесс. Не держите два процесса polling для одного Telegram-бота.
3. Отправьте боту `/version`. Ответ должен содержать `2026-09-24-r6`, имена `WB_TOKEN_1` и `WB_TOKEN_2` и пометку `задан` для каждого. Если версия другая, запущена старая копия кода: повторная отправка «остатки» этого не исправит.
4. После проверки версии отправьте «новинки», «остатки» и «аудит». Не публикуйте значения токенов и содержимое Secrets.

## Настройка

Установите зависимости из `requirements.txt` и задайте секреты окружения (в Streamlit Cloud: Settings → Secrets):

- `TELEGRAM_BOT_TOKEN` — токен Telegram бота;
- `WB_TOKEN_1`, `WB_TOKEN_2` — **разные** токены двух кабинетов, каждый с доступом к Контенту, Маркетплейсу (FBS) и Статистике. Старые названия `WB_API_TOKEN`, `WB_API_TOKEN_2` тоже поддерживаются, но названия `WB_TOKEN_1`, `WB_TOKEN_2` имеют приоритет;
- Форма отзывов использует `WB_TOKEN_1`. Если у этого токена нет доступа к Отзывам WB, задайте отдельный `WB_FEEDBACK_TOKEN` с нужными правами: он используется только формой отзывов. Токены не размещайте в файлах проекта;
- `MOYSKLAD_API_TOKEN` — токен МойСклад;
- `MOYSKLAD_STORE_NAME` — точное название склада, по умолчанию `МСК`;
- `SALES_DAYS` — период расчёта средней фактической продажи в календарных днях, по умолчанию `28`.

Запуск бота: `python tg_agent_new.py` либо кнопка на странице `bot_worker` в Streamlit. Не запускайте оба варианта одновременно: Telegram разрешает только один экземпляр polling для одного бота. Для непрерывной работы требуется постоянно работающий процесс; кнопка Streamlit запускает фоновый поток в рамках живого процесса приложения.

## Команды

- `остатки`: складывает FBS всех складов каждого из двух кабинетов; сравнивает сумму с МСК и с семидневной потребностью на основе фактических продаж обоих кабинетов за `SALES_DAYS`. Не выставляет остатки автоматически. Продажи, а не заказы; возвраты не учитываются как продажи.
- `новинки`: показывает товар с наличием на МСК, если карточка отсутствует или FBS остаток равен нулю **хотя бы в одном из двух кабинетов**. В сообщении указан конкретный кабинет, которому нужно выставить остаток. Проверка не использует дату создания карточки.
- `/diagnostics`: выводит по каждому кабинету количество карточек, баркодов и число ненулевых остатков по каждому FBS складу. Используйте, если «новинки» показывает слишком много нулей; команда не показывает значения токенов.
- `аудит`: проверяет все опубликованные карточки каждого кабинета: базовые поля, фото, баркод, габариты, вес, ТН ВЭД и обязательные характеристики предмета из справочника WB. Черновики и карточки в корзине не входят в метод списка опубликованных карточек. ТН ВЭД проверяется только если код присутствует в ответе API. Если WB не возвращает поле, бот сообщает число карточек, для которых код не удалось проверить; это не означает, что код пустой в личном кабинете. Аналогично отсутствующие в ответе ключи фото, названия, описания, габаритов и веса считаются непроверенными. Явно переданное пустое поле попадает в перечень замечаний.

Любой сбой источника данных останавливает проверку с сообщением об ошибке; отсутствие отклонений выводится только после успешного завершения запросов. Если отчёт МойСклад не содержит артикул в строке, скрипт ищет его в карточке товара МойСклад. Товары без артикула выводятся отдельным предупреждением и не останавливают сверку остальных товаров. Результат по ним остаётся непроверенным.
